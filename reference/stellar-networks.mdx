# Stellar Networks

Passphrases, RPC endpoints, Friendbot, contract addresses, and update cadence for every Stellar network supported by Wraith Protocol.

The canonical, machine-readable source of truth is the [contracts manifest](/contracts/manifest) (`contracts/manifest.json`) in the contracts repository. This page explains how to read it, which fields you can trust, how often records change, and how SDKs, indexers, and operators select a network safely. Contract addresses are **not** maintained here — they are read from the manifest.

## Network overview

| Network | Purpose | Status | Real value | Reset cadence | Wraith contracts |
|---|---|---|---|---|---|
| [Testnet](#testnet) | Development and integration testing | Live | No | ~quarterly (SDF reset) | Live |
| [Futurenet](#futurenet) | Experimental Soroban preview | Not deployed | No | On demand, without notice | Not deployed |
| [Mainnet](#mainnet) | Production | Pending | Yes | Never | Pending |

All values in the tables below are sourced from `contracts/manifest.json`. Do not copy addresses into your own config — read them from the manifest at runtime.

## Testnet

The SDF-operated Stellar testnet. This is where Wraith contracts are deployed today and where you should build and test integrations.

<Warning>
  The testnet is reset **approximately every quarter**. All accounts, balances, and contract state are wiped on reset. Watch [status.stellar.org](https://status.stellar.org) and the `#stellar-dev` channel for reset announcements.
</Warning>

### Connection details

| Property | Value | Field type |
|---|---|---|
| Network passphrase | `Test SDF Network ; September 2015` | immutable |
| Horizon URL | `https://horizon-testnet.stellar.org` | immutable, external |
| Soroban RPC URL | `https://soroban-testnet.stellar.org` | immutable, external |
| Friendbot URL | `https://friendbot.stellar.org?addr=<G_ADDRESS>` | immutable, external |

### Friendbot — fund a testnet account

New accounts need at least 1 XLM to activate. Friendbot hands out 10,000 XLM for free:

```bash
# Fund via curl
curl "https://friendbot.stellar.org?addr=GABC...YOURADDRESS"
```

```typescript
// Fund via the Stellar SDK
import { Server } from "@stellar/stellar-sdk/rpc";

const server = new Server("https://soroban-testnet.stellar.org");
await fetch(`https://friendbot.stellar.org?addr=${keypair.publicKey()}`);
```

<Note>
  Friendbot is only available on testnet and Futurenet. On mainnet you must fund
  accounts yourself with real XLM.
</Note>

## Futurenet

The SDF's preview network for upcoming Soroban features. **Wraith contracts are not deployed on Futurenet.** Use it only if you are building against unreleased Soroban capabilities or testing SDK changes that require a bleeding-edge node.

<Warning>
  Futurenet can reset at any time without notice and runs protocol versions that
  are not yet production-stable. Do not use it for integration testing.
</Warning>

### Connection details

| Property | Value | Field type |
|---|---|---|
| Network passphrase | `Test SDF Future Network ; October 2022` | immutable |
| Horizon URL | — | null (not available) |
| Soroban RPC URL | `https://rpc-futurenet.stellar.org` | immutable, external |
| Friendbot URL | `https://friendbot-futurenet.stellar.org?addr=<G_ADDRESS>` | immutable, external |

Horizon is `null` on Futurenet — there is no Horizon endpoint. Treat the field as undefined in code.

### Connecting with the SDK

```typescript
import { Server } from "@stellar/stellar-sdk/rpc";
import { Networks } from "@stellar/stellar-sdk";

const FUTURENET_RPC        = "https://rpc-futurenet.stellar.org";
const FUTURENET_PASSPHRASE = "Test SDF Future Network ; October 2022";

const soroban = new Server(FUTURENET_RPC);
```

<Note>
  `getDeployment("futurenet")` returns RPC and passphrase details but no Wraith
  contract addresses, because contracts are not deployed there. All contract
  fields are `null` with status `notDeployed`.
</Note>

## Mainnet

The Stellar public network. **Wraith contracts are not yet deployed on mainnet.** Contract addresses will be published in `contracts/manifest.json` and in `contracts/stellar/MAINNET_READINESS.md` once the mainnet deployment is complete.

<Warning>
  All mainnet contract addresses are pending. Do not use placeholder values in
  production. Subscribe to the `#announcements` channel for the mainnet launch
  notification.
</Warning>

### Connection details

| Property | Value | Field type |
|---|---|---|
| Network passphrase | `Public Global Stellar Network ; September 2015` | immutable |
| Horizon URL | `https://horizon.stellar.org` | immutable |
| Soroban RPC | Provider-dependent | external, null until you choose a provider |
| Friendbot | Not available | null |

The SDF does not operate a public Soroban RPC endpoint for mainnet. `sorobanUrl` is `null` in the manifest until you select a provider — it is an `external` field owned by the RPC provider, not by Wraith.

| Ankr | `https://rpc.ankr.com/stellar_soroban` | Yes | Budget option |

## Record provenance

Every network record in the manifest carries a `provenance` block that answers **where this data came from and how it was verified**:

```json
{
  "provenance": {
    "source": "@wraith-protocol/sdk/chains/stellar getDeployment(\"stellar\")",
    "verifiedAt": "2026-07-29",
    "method": "On-chain contract inspection via Soroban RPC, cross-checked against SDK TypeScript bindings"
  }
}
```

| Field | Meaning |
|---|---|
| `source` | The system or process that produced the record (e.g. the SDK's `getDeployment`, the mainnet deployment pipeline, Soroban RPC inspection). |
| `verifiedAt` | The date the record was last verified against the live chain. `null` means the record is pending and has not been verified on-chain. |
| `method` | How verification was performed: on-chain inspection, SDK binding cross-check, or pending deployment. |

Treat `provenance.source` as the authority for a contract address. If an address in your config does not match `provenance.source`, do not use it — it may be stale, a placeholder, or from an unofficial deployment.

## Trust boundaries

A network record crosses several trust boundaries. Know which party controls each field before you build on it.

| Field | Controlled by | Trust boundary | Implication |
|---|---|---|---|
| `networkPassphrase` | Wraith / Stellar protocol | Immutable | Never changes; safe to hard-code. |
| `horizonUrl` | SDF (testnet/mainnet) | Immutable, external | Wraith does not operate Horizon; SDF can change or retire the endpoint. |
| `sorobanUrl` | SDF (testnet) / RPC provider (mainnet) | External | Provider-operated. On mainnet you choose and authenticate the provider. |
| `friendbotUrl` | SDF | External, testnet only | Funds test accounts; not available on mainnet. |
| Contract addresses | Wraith (deployer/admin) | Mutable until mainnet | Can change on upgrade or redeploy. Always read the current value from the manifest. |
| Admin / upgrade keys | Wraith governance | External to your app | Controls contract upgrades; never embedded in client-side config. |

**Trust rule:** never treat an `external` field as part of your trust boundary. External endpoints can be rate-limited, change, or go down. Design for failover (see [Stellar Mainnet Deployment](/guides/stellar-mainnet-deployment) for RPC failover).

## Update cadence

| Layer | Changes when | Who updates | How to stay current |
|---|---|---|---|
| Network passphrase / horizonUrl | Never (immutable) | — | Hard-code safely. |
| RPC / Friendbot URLs | Provider changes endpoint | SDF / RPC provider | Re-read manifest on deploy; monitor provider status pages. |
| Contract addresses | Contract deploy or upgrade | Wraith deployer | Re-read manifest on each release; `verifiedAt` tells you when it was last confirmed on-chain. |
| Testnet state | ~quarterly SDF reset | SDF | Watch [status.stellar.org](https://status.stellar.org) and `#stellar-dev`. All balances and contracts wiped. |
| Futurenet state | On demand, without notice | SDF | Do not rely on Futurenet for integration testing. |

Re-deploying your application does **not** refresh contract addresses. Read the manifest at runtime (or at build time via a CI step) so upgrades are picked up without a redeploy.

## Safe network selection

SDKs, indexers, and operators each select a network differently, but all must read from the manifest and respect field types.

### SDK (client application)

Use `Chain.Stellar` (or the `"stellar"` string) to select the network, then read `getDeployment("stellar")`. Reject any network whose contract address is `null` or `pending` unless you are explicitly targeting testnet development.

```typescript
import { getDeployment, DEPLOYMENTS } from "@wraith-protocol/sdk/chains/stellar";
import { Server } from "@stellar/stellar-sdk/rpc";

async function selectNetwork(network: "testnet" | "futurenet" | "mainnet") {
  const deployment = getDeployment(network);

  // Guard: do not point a client at a network with no live contracts.
  if (!deployment.contracts.announcer) {
    throw new Error(
      `No live announcer contract on ${network}. status=${deployment.status}. ` +
      "Use testnet for development or wait for mainnet launch.",
    );
  }

  // Guard: never run real value against pending/unverified records.
  if (network === "mainnet" && deployment.provenance?.verifiedAt === null) {
    throw new Error("Mainnet contracts are pending verification. Do not use in production.");
  }

  const soroban = new Server(deployment.sorobanUrl);
  return { deployment, soroban };
}

// Example: safe testnet selection
const { deployment, soroban } = await selectNetwork("testnet");
```

`getDeployment` returns the record for the active SDK version. To see every network the SDK knows about, use `DEPLOYMENTS`. To read the full manifest (including `null`, `external`, and `pending` annotations) fetch `contracts/manifest.json` directly.

### Indexer

An indexer scans announcement events from Soroban RPC. It must:

1. Read the announcer contract address from the manifest (not a hard-coded placeholder).
2. Skip networks where `contracts.announcer.address` is `null`.
3. Track `lastProcessedLedger` and respect RPC retention windows (~17,280 ledgers ≈ 24 hours on public RPC).
4. Use an external RPC provider on mainnet with failover.

```typescript
import { getDeployment } from "@wraith-protocol/sdk/chains/stellar";
import { Server } from "@stellar/stellar-sdk/rpc";

async function buildIndexer(network: string) {
  const deployment = getDeployment(network);
  const announcerId = deployment.contracts?.announcer?.address;

  if (!announcerId) {
    throw new Error(`No announcer contract on ${network}; nothing to index.`);
  }

  const rpc = new Server(deployment.sorobanUrl);

  const events = await rpc.getEvents({
    startLedger: lastProcessedLedger,
    filters: [{
      type: "contract",
      contractIds: [announcerId],
      topics: [["announce"]],
    }],
  });

  return events;
}
```

If `sorobanUrl` is `null` (mainnet before you pick a provider), refuse to start until the operator configures an external RPC endpoint.

### Operator

An operator running a Spectre TEE instance on mainnet selects:

* **Network:** `mainnet` with `networkPassphrase` = `Public Global Stellar Network ; September 2015`.
* **RPC:** an external provider (Validation Cloud, QuickNode, Ankr, or self-hosted). Configure primary + fallback.
* **Contract IDs:** read from the manifest after mainnet launch; never use placeholder `CPLACEHOLDER…` values.
* **Admin key:** held in cold storage / multisig; controls contract upgrades. It is outside the application's trust boundary.

```bash
# .env — operator config, read manifest values at runtime
STELLAR_NETWORK=mainnet
STELLAR_NETWORK_PASSPHRASE="Public Global Stellar Network ; September 2015"
STELLAR_HORIZON_URL=https://horizon.stellar.org
STELLAR_RPC_URL_PRIMARY=https://mainnet.stellar.validationcloud.io/v1/<API_KEY>
STELLAR_RPC_URL_FALLBACK=https://<slug>.stellar-mainnet.quiknode.pro/<API_KEY>
# Contract IDs are resolved from contracts/manifest.json, not hard-coded
```

See [Stellar Mainnet Deployment](/guides/stellar-mainnet-deployment) for the full operator runbook: hardware, funding, monitoring, upgrade governance, and incident response.

## Field types: null, external, pending, immutable

Manifest fields carry type annotations that tell you how to handle them in code.

| Type | Meaning | Example | Handling |
|---|---|---|---|
| `immutable` | Never changes after the record is created. | `networkPassphrase` | Safe to hard-code or cache indefinitely. |
| `external` | Owned by a third party (SDF, RPC provider, subgraph host). Wraith does not control it. | `sorobanUrl` on mainnet | Read at runtime; design for failover; do not treat as part of your trust boundary. |
| `pending` | Not yet deployed or determined. | Mainnet contract addresses | Do not use in production. Track readiness in `contracts/stellar/MAINNET_READINESS.md`. |
| `null` | Field is absent or not applicable for this network. | `friendbotUrl` on mainnet; `horizonUrl` on Futurenet | Treat as `undefined` in code; branch on presence before use. |

### Code example: handling each field type

```typescript
import { getDeployment } from "@wraith-protocol/sdk/chains/stellar";

const deployment = getDeployment("stellar");

// immutable — safe to hard-code
const passphrase = deployment.networkPassphrase;

// external — read at runtime, plan for failover
const rpcUrl = deployment.sorobanUrl;
if (!rpcUrl) {
  throw new Error("sorobanUrl is null/external — configure an RPC provider before connecting.");
}

// pending — address absent until deployment
const announcer = deployment.contracts.announcer;
if (!announcer.address || announcer.status === "pending") {
  throw new Error("Announcer not deployed on this network.");
}

// null — field not applicable
const friendbot = deployment.friendbotUrl; // null on mainnet
if (friendbot) {
  await fetch(friendbot.replace("<G_ADDRESS>", address));
}
```
